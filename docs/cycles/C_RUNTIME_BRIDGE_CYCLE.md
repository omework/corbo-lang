# C runtime header, generated layouts and aggregate operands

Date: 2026-11-18. Scope: core/compiler interoperability plus packaging of the
existing C memory runtime. The Rust bootstrap remains frozen. This implements
the previously accepted unchecked-C contract; it adds no ownership checking or
implicit move semantics to C. No independent adversarial audit, randomized
campaign or mutation campaign was performed or incorporated in this cycle.

## Implemented

- `runtime/corbo_runtime.h` is the canonical C11 definition of primitive aliases,
  regions, pools, allocation descriptors and map storage. The existing fragments
  use these definitions rather than maintaining duplicate layouts.
- `runtime/runtime_api.c.inc` exposes memory allocation, stack marks/rewind,
  region and pool operations, map operations and page reclamation. Pool release
  invokes the descriptor's destroy callback before recycling its slot.
- `runtime/corbo_runtime.c` and `scripts/build_c_runtime.py` package those existing
  implementations as a C-owned static memory runtime. Generated Corbo continues
  to embed the same implementation. A separately compiled C helper calls that
  embedded instance through the public header; it must not link a second copy
  of the standalone archive.
- corboc generates nominal typedefs, struct/enum field aliases and enum tag
  constants. Per-member anonymous unions retain the existing layout. An operand
  has a local `corbo_type_<binding>` typedef. Placed arrays expose their logical
  wrapper, not the backend's storage pointer. User headers follow the concrete
  type declarations, so their declarations can refer to those types.
- `${binding}` accepts any available typed binding, including aggregates and
  descriptors. Mutable bindings retain their storage. Immutable scalar operands
  remain rvalues; immutable aggregates expose const views. Type/availability
  checks still occur at the crossing; opaque C effects are not entered into the
  Corbo dependency graph. C code can deliberately mutate a target that has a
  checked-language loan: that is the explicitly accepted trust boundary.

## Defects and validation corrections

- Runtime layouts initially existed only inside emitted fragments. They are now
  defined once in the public header, shared with the standalone implementation.
- Flat enum field aliases could collide for underscore-containing variant/field
  spellings. Variant-name components now escape underscores, and tag constants
  have a separate prefix from nominal type aliases. The naming fixture checks
  the colliding shapes and a source field named `switch`.
- User headers previously appeared before nominal type declarations. Emission
  now puts them after concrete definitions; the external helper header uses a
  generated `Corbo_Point` declaration.
- The first Linux archive check used the host archiver on target ELF objects and
  failed to resolve runtime symbols. The completed run uses the target archiver
  and recreates the archive from scratch.
- The first Windows external-helper link also supplied the standalone archive,
  producing duplicate runtime definitions. It did not finish the full suite.
  The corrected test uses one implementation: the archive for a C-owned program,
  or generated Corbo's runtime for its C helpers. The completed Windows run passed.
- A naming fixture initially used reserved `A` as an enum variant and was refused
  by the parser. It was changed to `Alpha`, retaining the intended naming collision.

## Reproduce

```sh
python3 scripts/runtime_sources.py --check
python3 scripts/build_c_runtime.py --out build/c-runtime
python3 validation/check_c_runtime_bridge.py \
    --corboc build/corbo-install/bin/corboc --keep /tmp/corbo-c-runtime
```

The test accepts `--cc`, `--ar` and `--runner` for a target toolchain and execution
wrapper. `--reuse-c DIR` reuses the portable fixture C; the external helper is
regenerated with that run's header path. Target-specific `@asm` is not involved
in these fixtures. Linux container paths must be visible inside the mounted
workspace. Artifacts for this run are under `/tmp/corbo-c-bridge/` and
`/private/tmp/corbo-iter-std/c-runtime-final/`.

## Limits

- Windows evidence is Wine execution, not native Windows. Windows ARM64 remains
  explicitly deferred by the user; Linux ARM64 was not executed here.
- The public archive is the memory runtime, not a standalone task scheduler API.
  Task operands use the generated program's task layouts. Default Corbo package
  linking still embeds runtime fragments; a future native backend can call the
  public memory interface without changing that interface's C responsibilities.
- The runtime header contains shared runtime types. Program-specific nominal
  declarations are generated in the program's translation unit, not in a new
  separately installed per-program header.
- C11 layouts are experimental and version-matched. Cross-version ABI stability,
  C++ compatibility, arbitrary user over-alignment and every aggregate shape
  are not established by these runs.
- C copies, aliases, retained addresses, cursor rewinds and resource cleanup are
  developer responsibilities. A raw C write does not update checked dependency
  metadata. Active region descriptors must remain at stable addresses. Rewind
  is not a destructor traversal and cannot make unfinished tasks safe.
- No ASan campaign was run for this cycle; the completed sanitizer evidence is
  the fatal UBSan/UB-trap executions above.
