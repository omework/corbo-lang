# Corbo runtime

The active runtime algorithms are written in [Corbo](corbo/README.md), separate
from the compiler's lexer, parser, analysis and code generation. Datastacks,
regions, pools, collections, scheduling, cleanup and reactor state transitions
use these sources. Explicit unchecked bindings provide the C ABI, atomics,
callbacks and operating-system operations for the current C backend.

The following C fragments remain the selectable comparison implementation:

| Source | Responsibility |
| --- | --- |
| [memory/datastack.c.inc](memory/datastack.c.inc) | Fixed datastack, regions, virtual-memory reservation and commitment |
| [memory/pools.c.inc](memory/pools.c.inc) | Pool slots, allocation handles and release |
| [memory/reclaim.c.inc](memory/reclaim.c.inc) | Page reclamation |
| [memory/region_release.c.inc](memory/region_release.c.inc) | Global region release |
| [collections/vector.c.inc](collections/vector.c.inc) | Vector append and access |
| [collections/vector_owned.c.inc](collections/vector_owned.c.inc) | Byte append, extraction and owned-element cleanup |
| [collections/hashmap.c.inc](collections/hashmap.c.inc) | HashMap storage, lookup, insertion, replacement, removal and cleanup |
| [async/scheduler.c.inc](async/scheduler.c.inc) | Task scheduling and wakeup infrastructure |
| [async/readiness.c.inc](async/readiness.c.inc) | Descriptor cohorts, aggregate Unix interests and task wakeups |
| [async/completion.c.inc](async/completion.c.inc) | Per-operation Windows IOCP completion and wakeups |
| [async/values.c.inc](async/values.c.inc) | Task states, results and execution values |
| [async/threads.c.inc](async/threads.c.inc) | Worker threads, joins and runtime synchronization |

These are C fragments for the current C backend, assembled in their existing
dependency order. They are not independent translation units. The Corbo implementation preserves
the same layouts, interfaces and observable behavior. `CORBO_THREADED` sections in page
reclamation are included only when the backend requests the threaded variant.

## Compiler and STD boundary

- [corboc/src](https://github.com/omework/corboc/tree/main/src) owns parsing, static representations, rule checking,
  placement analysis and lowering. It still maps native collection operations
  and their dependencies to runtime calls.
- `runtime/corbo/` owns the active algorithms; the C fragments above are the reference.
- `stdlib/src/collections.crb` declares the public root STD exports for the
  existing native Vector, HashMap and String types. It does not implement them.
- Type-specific cleanup and code for a particular program remain generated by
  the backend. This is a source separation, not removal of every native-type
  hook from the compiler or a conversion of collections to ordinary Corbo types.

## Editing runtime code

[corbo_runtime.h](corbo_runtime.h) defines the shared C11 memory layouts and
public datastack, pool, region and map operations. [corbo_runtime.c](corbo_runtime.c)
assembles the reference memory fragments. The build tool defaults to compiling
the Corbo implementation into a static library with the same C ABI:

```sh
python3 scripts/build_c_runtime.py --out build/c-runtime
# Optional reference build:
python3 scripts/build_c_runtime.py --implementation c --out build/c-reference
```

The Corbo build requires a compatible `corboc` supporting `--emit-runtime-c`;
pass `--compiler /path/to/corboc` if it is not installed in the sibling compiler
checkout. The C reference build requires only the C toolchain.

The output is `build/c-runtime/include/corbo_runtime.h` and
`build/c-runtime/lib/libcorbo_runtime.a`. Select the target compiler and archiver
with `--cc` and `--ar`. A C-owned program initializes and shuts down this runtime.
The standalone archive exposes the memory API, not a public scheduler interface.

Generated Corbo embeds the same header and the implementation selected by the
compiler source lock (currently `corbo`). An external C helper
can include the header and call the public functions supplied by that generated
translation unit, sharing its runtime state. Do not link a second standalone
runtime archive into that executable. Program-specific Corbo type declarations
are emitted by corboc before foreign headers and statements. This keeps emitted
C self-contained; it is not yet a change to default package linking.

C ownership, borrowing, lifetimes, descriptor copies, thread synchronization,
cleanup and cursor rewinds remain developer responsibilities inside `@unchecked`.
Active region descriptors must remain at stable addresses. The header/ABI must
match the compiler version. See the [foreign-C contract](../docs/FOREIGN_C.md#corbo-types-and-the-runtime-library)
and [executed validation](../docs/cycles/C_RUNTIME_BRIDGE_CYCLE.md).

Edit the Corbo sources in `runtime/corbo/` here, commit the runtime change, and deliberately
update the compiler repository’s `corbo.lock` to that revision. Prepare its pinned
source cache and regenerate the embedded compiler resource from the compiler root:

```sh
python3 scripts/runtime_sources.py
python3 scripts/runtime_sources.py --check
```

The generated file is
`src/runtime_sources/runtime_sources.crb` in the compiler repository. Do not edit its byte
arrays. It embeds the compiled implementation so installed compilers do not need to locate
runtime source files when compiling a user package. Regeneration uses Python as
a development utility; running the compiler does not require Python. The same
commands in this language checkout are compatibility forwarders. They locate a
sibling `corboc/` checkout (or `CORBOC_SOURCE_ROOT`) and use the compiler’s locked source cache. An explicit `--source` checkout
must match the lock; ordinary documentation commits here do not change the pin. See [the repository boundary](../docs/COMPILER_REPOSITORY.md).

The runtime uses the repository's dual [MIT](../LICENSE-MIT) /
[Apache-2.0](../LICENSE-APACHE) license.

## Network wait identities

Unix waits are intrusive registrations in the waiting task frames. A descriptor
cohort has a monotonically increasing generation token; its native queue entry
carries the union of read and write interests. Dispatch detaches matching waiters
under the scheduler lock before publishing readiness, then rearms the remaining
interests. A delayed event with no active generation is ignored. Register/rearm
failures wake the affected waiters with an error. This preserves the existing
level-readiness retry contract: waking a reader does not reserve socket bytes.

Windows uses an independent OVERLAPPED request per operation. The runtime keeps
the task and request live until that request is dequeued from IOCP, including
operations that completed synchronously at submission. It clears the request's
runtime task link before publishing completion. No descriptor-global waiter slot
is shared by concurrent operations.

Native queue operations remain in `stdlib/src/sys/net/reactor/` as target-selected
Corbo `@asm` functions. The compiler authenticates only the STD runtime hooks
through package-link metadata; user code cannot forge a trusted hook by spelling
its name.

See the [Corbo runtime source guide](corbo/README.md) and
[implementation/parity report](../docs/cycles/CORBO_RUNTIME_CYCLE.md).
